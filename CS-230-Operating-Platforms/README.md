# CS 230 – Operating Platforms

## The Gaming Room Software Design Document

This repository contains my completed software design document for The Gaming Room, developed as part of CS 230 at Southern New Hampshire University. The project involved analyzing software requirements, evaluating different operating platforms, and recommending an architecture for a game application that could support multiple devices and users.

### 1. Briefly summarize The Gaming Room client and their software requirements.

The Gaming Room was a client looking to expand its existing Android-based game, *Draw It or Lose It*, to additional platforms. The game involves teams competing to guess images displayed on the screen. The client needed a system that could support multiple teams and players, maintain unique game and team names, and ensure only one instance of a game could exist at a time. The application also needed to be scalable, secure, and accessible across different operating platforms.

### 2. What did you do particularly well in developing this documentation?

I believe one of my strengths was identifying the technical requirements and comparing different operating platforms to determine which would best support the client's needs. I was able to consider factors such as memory management, storage, security, and compatibility when making recommendations. I also focused on organizing the information so that both developers and the client could understand the reasoning behind the proposed design.

### 3. What about the process of working through a design document did you find helpful when developing the code?

Working through the software design document helped me understand the importance of planning an application's structure before beginning development. Breaking down the requirements made it easier to determine how different components should interact and what functionality needed to be implemented. During the Java development exercises, I could see how defining relationships between classes and understanding client-server communication helped create a more organized application.

### 4. If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

If I could revise one part of my documentation, I would expand the evaluation of security and scalability. Although I addressed these areas, I think including more specific examples of authentication, data protection, and how the application would respond to increased traffic would make the document stronger. I would also provide additional explanations of how the recommended architecture could accommodate future improvements.

### 5. How did you interpret the user's needs and implement them into your software design? Why is it so important to consider the user's needs when designing?

I approached the client's needs by identifying the main functionality of the game and determining what technical requirements were necessary to support it. For example, maintaining unique game instances and supporting multiple users influenced the application's architecture and data management. I also considered the importance of accessibility across different devices. Understanding user needs is essential because even a technically functional application can be unsuccessful if it does not meet the expectations of the people using it.

### 6. How did you approach designing software? What techniques or strategies would you use in the future?

My approach involved reviewing the client's requirements, identifying potential technical challenges, and comparing available operating platforms before recommending a solution. I found that evaluating the advantages and disadvantages of each platform helped me make more informed design decisions. In future projects, I would continue using requirements analysis, object-oriented design principles, and architectural comparisons. I would also incorporate more testing and documentation throughout development to identify potential issues earlier and make the software easier to maintain.

## Conclusion

This project helped me better understand how software architecture, operating systems, and client requirements influence the development process. It also reinforced the importance of creating clear documentation before writing code. The experience has given me a stronger foundation for approaching future software development projects and communicating technical decisions effectively.
